NAESOAU account linkage - deployment notes

1. Back up the Supabase database.
2. Run auth-user-link-migration.sql in Supabase SQL Editor. It adds a nullable
   user_id foreign key and unique index to registrations. Existing rows are
   intentionally NOT linked automatically; email matching alone is not safe.
3. Upload the updated register.js with the existing package. New membership
   registrations are now submitted with the signed-in Supabase auth user ID;
   the email field is taken from the verified account and made read-only.
4. IMPORTANT: the migration deliberately does not change RLS policies. Before
   removing the old anonymous registration INSERT policy or creating student
   policies, inspect the policy list returned at the end of the SQL script.
   Remove the old broad anonymous INSERT policy, then add an authenticated
   INSERT policy requiring user_id = auth.uid(), and a student SELECT policy
   requiring user_id = auth.uid(). Keep the separate executive permission
   policies intact. Never rely on the front-end guard alone.
5. Payments still identify registrations by reg_no in the current app. Do not
   enable student payment reads until a policy safely joins payments.reg_no to
   registrations.reg_no where registrations.user_id = auth.uid().
6. Existing registrations need a verified account-claim workflow or a manual
   executive-reviewed link. Do not bulk-link by email without verification.

The public landing page remains public; protected pages require a Supabase
session. Database RLS must independently enforce access.
